# 合同智能审查平台 · 秋招面试与验收脚本

> [!important] 这份笔记为什么单独存在
> 通用模板的"交付物"是给客户的软件。**本项目的交付物是"我在面试里能讲出来的东西"。**
> 软件只是证据。所以每个技术决策都必须能反向回答："面试官会怎么追问，我答什么。"

## 1. 简历怎么写

### 项目条目（4~6 行，STAR 收敛）

~~~text
合同智能审查平台 | Java 全栈 · 个人项目 | 2026.10（5 天冲刺）

· 面向法务审合同场景，实现"上传 → 要素抽取 → 规则校验 → AI 风险识别 → 人工复核 → 报告页"
  完整闭环，后端 Spring Boot 3.3 / Java 21 / MyBatis-Plus / MySQL / Redis，前端 Vue 3 + Element Plus，Docker Compose 一键启动。
· 设计"规则引擎 + AI 增强"双通道架构：金额一致性、日期逻辑、必备条款缺失等确定性校验由纯函数规则引擎实现，
  不依赖外部服务、结论可复现；AI 仅产出候选风险条目，两者互不调用，只在工作流层汇合。
· 解决大模型引用幻觉问题：实现三级证据对齐校验，AI 给出的风险条款必须能在原文指定字符区间命中，
  否则标记 EVIDENCE_MISMATCH 并强制转人工，无原文定位的结论不进入报告。
· 建立降级与成本治理：AI 通道异常时规则审查与人工流程不受影响；按文本哈希缓存审查结果，
  设置片段上限与令牌桶限流，重复提交幂等去重。
· 5 天期限内主动砍范围保质量：推迟统计看板、批量审查、报告导出与 OCR，
  用 JUnit 5 严格覆盖规则引擎与证据对齐，外部依赖以可切换 Mock 通道测试异常分支。
~~~

> [!tip] 加分的写法
> 把"5 天"写进去不是减分项，而是**主动展示范围管理能力**。
> 面试官会立刻追问"5 天你怎么取舍的"——这正是你准备好的答案（见下方"期限与取舍"小节）。

### 一句话版本（自我介绍/电梯陈述用）

> 我做了一个合同智能审查平台，重点不在"接了 AI"，而在**给概率性的 AI 输出加上工程约束**：AI 只能产出带原文证据和置信度的候选结论，能不能采信由确定性规则和人工决定。

### 写简历时的红线

- ❌ 不写"精通"、不写"高并发"（除非真有压测数据，见 [07](07-change-and-delivery.md#已知限制)）。
- ❌ 不写没做过的模块名充数。
- ✅ 每一个技术名词，都要能答出"为什么用它、不用它会怎样"。

## 2. 演示脚本

### 3 分钟版（现场演示，含"故意失败"）

| 时间 | 步骤 | 我要说的话（要点） |
| --- | --- | --- |
| 0:00-0:20 | 打开合同列表 | "这是一个审查工作台，链路是上传→抽取→规则→AI→复核→报告。" |
| 0:20-0:50 | 上传虚构采购合同，展示解析结果 | "解析失败会显式报错，不会产生半个要素。" |
| 0:50-1:10 | 点击要素提取，点开一个字段 | "每个字段都能点回原文片段，因为存了字符区间——这是后面证据校验的基础。" |
| 1:10-1:40 | 点击规则校验 | "这一步**完全不联网**，纯函数，同输入必然同输出，有单测。注意这里没有命中不等于通过，抽不到要素的规则会返回'无法判定'。" |
| 1:40-2:20 | 点击 AI 审查，展示一条风险条目 | "注意它带原文引用、置信度和模型版本。**这是候选，不是结论。**" |
| 2:20-2:45 | 展示降级：把一条证据区间改坏后重跑 | "证据定位不上，系统不会猜，直接转人工。这是我这个项目最想解决的事。" |
| 2:45-3:00 | 采信一条、驳回一条，打开报告页 | "报告里规则结论、AI 建议、人工意见分栏显示，谁改的、什么时候改的都能查到。" |

> [!tip] 演示前必做的准备
> 1. **录一段 3 分钟视频兜底**——现场网络、Docker、AI 额度任何一个出问题都不至于开天窗。
> 2. 提前把 DeepSeek 调用结果**缓存好**（按 `textHash` 缓存），现场即使断网也能展示 AI 结果。
> 3. "故意失败"那一段用**改坏的桩数据**触发，不要依赖真实模型返回错误。

### 15 分钟版（技术面深聊）

在 3 分钟版基础上追加：

1. **打开测试代码**，现场演示一个失败测试 → 实现 → 通过的循环（证明 TDD 不是嘴上说的）。
2. **展示异常分支测试**：超时、限流、非法 JSON 三种，说明错误码分别是 `AI_TIMEOUT` / `AI_RATE_LIMITED` / `SCHEMA_INVALID`，以及测试如何通过切换 `AiClient` 实现免网络覆盖。
3. **展示 `docker compose up`** 从零起环境（提前录屏兜底，现场网络不可控）。
4. **展示 Git 提交历史**：`test(...)` → `feat(...)` → `docs(specs): ...` 的原子提交序列。

## 3. 面试问答（按模块）

> [!tip] 用法
> 每答完一个模块的问题，就在对应模块笔记的「面试可讲点」里补一条。
> 答不出来的先写进下面的「待补」区，别编。

### 3.1 架构与选型

| 问题 | 我的答案要点 |
| --- | --- |
| 为什么不用微服务？ | **两个原因，第二个更重要。** 一是 5 天期限、单人开发、无真实流量，微服务只增加运维成本；二是**我没有微服务实践经验**，硬搭一个只会得到"照教程搭出来的东西"，反而经不起追问。我的替代方案是模块化单体 + 明确的边界纪律：模块间只走接口、禁止跨模块读表、依赖方向单向、`rule` 与 `ai-review` 互不调用。**架构能力体现在边界划得清，不体现在拆得多。** |
| 为什么不用 Flyway？ | 坦白说是我没学过，而 5 天期限内不值得为它花一天。我用 `schema.sql` + `data.sql` + `CREATE TABLE IF NOT EXISTS` 满足了"启动即建表、可重复执行"。**我清楚这笔技术债的代价**：没有版本化迁移，改表只能手工 ALTER，多人协作环境会出问题。如果给我一周，Flyway 是第一件要补的事。 |
| 5 天你怎么取舍的？ | 我先定死一条线：**证据对齐、降级路径、审计只追加**三项绝不砍，因为它们是这个项目的唯一技术卖点。其余全部按"演示时能不能看出来"排序砍，砍掉了统计看板、批量审查、报告导出、OCR。**砍范围，不降质量。** 最后 20 个任务按天排，每天必须有一个可演示的产物，避免最后一天才发现跑不起来。 |
| 模块之间怎么保证不互相污染？ | 两条硬纪律：`rule` 与 `ai-review` **互不调用**（确定性判断不付概率代价），两者只在 `workflow` 汇合；跨模块禁止直接读表。违反了先改架构文档再改代码。 |
| 你系统里最重要的不变式是什么？ | I-02：**无原文定位的 AI 结论不得进入正式结论**。这条把"AI 会不会胡说"变成了一个可机器校验的问题，而不是靠信任。 |
| 为什么把证据对齐做成独立一层？ | 因为模型会幻觉出不存在的条款，而且幻觉的形式是"看起来很像的改写"。如果信任模型的引用，报告里会出现无法核实的判断，法务的信任成本极高。所以对齐必须是机器校验、必须有单测、失败必须显式降级。 |

### 3.2 规则引擎

| 问题 | 我的答案要点 |
| --- | --- |
| 规则为什么不用 AI 做？ | 金额大小写不一致、签署日晚于生效日、缺必备条款，这些都是**确定性判断**。用 AI 做会引入不确定性、成本和不可复现性，还无法写严格单测。AI 留给"语义模糊"的部分（比如"这条违约责任是否明显不对等"）。 |
| 怎么保证同输入同输出？ | 规则执行是纯函数：输入 = 归一化文本 + 要素，输出 = `RuleFinding[]`，内部不读时间、不读随机数、不联网。有"连续执行两次结果完全一致"的回归测试。 |
| 规则怎么扩展？ | 每条规则实现统一接口（`ruleCode` / `severity` / `evaluate(context)`），引擎按注册表遍历。新增规则不改引擎。**但我没做可视化规则编排**——这是已知限制，因为本期没有真实用户来驱动这个需求。 |
| 边界情况怎么处理？ | 要素缺失时不猜：规则返回"无法判定"而不是"通过"。**"通过"和"无法判定"必须是两种不同结果**，否则缺失必备条款会被当成合规。 |

### 3.3 AI 接入（重点追问区）

| 问题 | 我的答案要点 |
| --- | --- |
| 怎么防止大模型胡说？ | 三层：① 提示词里约束输出 schema；② 返回后做 schema 校验，非法就 `SCHEMA_INVALID` 显式失败，**不用默认值兜底**；③ 证据对齐——quote 必须能在原文坐标命中，否则 `EVIDENCE_MISMATCH` 转人工。最后 AI 结论永远是"候选"，人工采信后才生效。 |
| 大模型返回的引用被改写了怎么办？ | 对齐算法不只做严格匹配，还做归一化匹配（全角/半角、空白折叠），但**归一化后的区间必须回映射到原文坐标**——这正是我踩过的坑，也是我专门写了测试的地方。 |
| AI 成本怎么控制？ | ① 按 `textHash` 缓存审查结果，同文本第二次 0 次外部调用；② 单合同片段数上限；③ Redis 令牌桶限流 + 单日预算上限；④ 超预算时明确拒绝并提示，不静默降级为"审查通过"。 |
| AI 挂了系统还能用吗？ | 能。规则审查和人工复核完全不依赖 AI。AI 不可用时对应任务标 `AI_UNAVAILABLE`，界面明确提示，规则结论照常展示（I-04）。这是设计出来的，不是碰巧。 |
| 重试策略？ | 超时/限流最多重试 1 次，之后转人工。**不做无限重试**——这是从工作流方法里抄来的纪律：重试掩盖的根因，最终会以更贵的方式出现。 |
| 为什么不用 Spring AI 这类框架，自己写 HTTP？ | 我只有 DeepSeek 一个供应商，自写客户端约 100 行，没有版本不确定性，供应商耦合集中在一个 `DeepSeekClient` 类里。更关键的是**可测试性**：我把调用封在 `AiClient` 接口后面，测试注入桩实现就能覆盖超时/限流/非法 JSON 三类分支；同一个开关（`app.ai.enabled=false`）还直接复用为演示时的降级手段，**一个设计同时解决测试和降级两个问题**。 |
| 落库的 AI 数据你存了什么？ | 风险类型、原文引用、字符区间、置信度、模型版本、原始响应摘要。存模型版本是为了"结论可追溯"——半年后要能回答"这条是谁在哪个模型下判的"。 |
| 有没有做评测集？ | 没有，这是已知短板。我只有少量虚构合同做回归。我更愿意说清楚：没有评测集的情况下，我把 AI 定位成"候选建议"而不是"自动结论"，这是在缺评测能力时更诚实的架构选择。 |

### 3.4 并发、幂等与数据一致性

| 问题 | 我的答案要点 |
| --- | --- |
| 批量审查怎么做的？ | 串行执行 + 令牌桶节流 + 暂停/恢复。刻意不并发：外部平台有速率限制，并发放大的是失败而不是吞吐。 |
| 幂等怎么保证？ | 以 `textHash`（文本内容哈希）作为幂等键 + 分布式锁。同内容重复提交返回已有任务，不重复调用模型。 |
| 事务边界怎么划的？ | 远程调用（AI、文件写入）**绝不放事务里**。事务只包住本地的状态写入。否则一次模型超时会把数据库连接池拖死。 |
| 租户隔离怎么防止漏掉？ | Repository 层统一注入 `tenantId` 条件，而不是靠每个 Service 记得加。并专门写了"忘记带 tenantId"的失败测试——用测试锁住这个不变式，而不是靠代码评审。 |

### 3.5 认证与安全

| 问题 | 我的答案要点 |
| --- | --- |
| 登出为什么要幂等？ | 用户重试、前端重复调用，诉求都是"让这个令牌失效"——**而它已经失效了**。失败响应只会让前端多写一个无意义分支。所以我把登出设为免认证：令牌本身就是凭证，有效就拉黑，无效就什么都不做。**这个结论是测试逼我改的**：我原本要求登出必须已认证，结果"重复登出返回 401"，我选择改代码而不是改测试。 |
| 密码错误和账号不存在为什么返回同一个错误码？ | 否则登录接口会变成**账号探测器**——攻击者能靠错误码区分出哪些用户名存在。防爆破交给锁定计数，不靠差异化提示。 |
| 锁定状态为什么落库而不是只放 Redis？ | 清一次缓存就等于给攻击者重置了爆破机会。**安全状态不能依赖可被清空的存储。** |
| 登出黑名单为什么设 TTL？ | TTL = 令牌剩余有效期。令牌自然过期后再拉黑只是白占内存。这样黑名单大小有上界 = 一个有效期窗口内的登出量，不会无限膨胀。 |
| JWT 里为什么不能放邮箱、真实姓名？ | **JWT 是签名不是加密**，base64 解开就是明文。所以我只用 `UserView` 投影控制对外字段，并有断言确保响应里不出现 `passwordHash`。 |
| 失败计数为什么先检查锁定再验密码？ | 否则锁定期内仍在跑 BCrypt，**锁定形同虚设**，还白白消耗 CPU。校验顺序本身就是设计。 |

### 3.6 CRUD 相关问题（别怕被问到，这是加分点）

| 问题 | 我的答案要点 |
| --- | --- |
| 你这个项目的 CRUD 有什么特别的？ | 单看每一条都不特别，但**每条 CRUD 都挂着一个真实问题**。比如查询要保证多租户隔离不能靠人记得写条件；删除要级联清理文件和缓存。**我不觉得有 CRUD 是缺点，我觉得"CRUD 里没有问题"才是缺点。** |
| **租户隔离你怎么保证不遗漏？** | **不靠自觉，靠构建时检查。** 我写了一个架构测试扫描所有 Mapper 的 SQL，缺 `tenant_id` 就 `mvn test` 失败并指出是哪个类。而且我**验证过这个测试真的会失败**——故意删掉一个条件，它精确报出了 `ContractTextMapper`。另外单独写了一个"确实扫到了 Mapper"的断言，防止"扫到 0 个所以假绿"。 |
| 为什么另一个租户看到的是 404 而不是 403？ | 403 等于确认"这份合同存在，只是不归你"，接口就变成了合同 id 探测器。**不确认自己不该确认的信息。** |
| 删除合同你怎么做的？ | 两段式：先软删除让用户立刻看到结果，再清理磁盘文件、正文行和 **Redis 里该 `textHash` 的 AI 缓存**。清理失败进重试队列，并记录未清理完的 `textHash`。 |
| 为什么删除要清缓存？不清会怎样？ | AI 结果按 `textHash` 缓存。只删库不清缓存，**用户重传同一份合同会拿到与本次无关的过期结论**——而且看起来完全正常，这是最危险的一类 bug。**缓存键按内容算，失效就必须按内容定向清除。** |
| 为什么用文件哈希做幂等而不是文件名？ | 同一份文件改名后重传应当命中已有记录。**幂等看内容，不看名字。** |
| 超限校验为什么写在算哈希之前？ | 否则一个 1GB 的非法文件会被完整读一遍算哈希，白费 IO。**校验顺序也是设计。** |
| 分页怎么做的？ | 常规 `LIMIT/OFFSET`，`size` 收敛在 1~100 防止 `?size=100000` 拖垮数据库。我清楚深分页会退化（`OFFSET` 很大时要扫过前面所有行），演示数据量下没问题；数据量上去要换成游标分页。**这是已知限制，不是我不知道。** |
| 非法参数怎么处理的？ | 显式报错，不静默忽略。这里踩过一个坑：未知状态值抛的 `IllegalArgumentException` 一开始落到了兜底处理器返回 **500**，真实环境复验才发现，改成 400。**服务层测试覆盖逻辑，HTTP 层测试覆盖映射，两者不能互相替代。** |

### 3.7 AI 成本与额度管理

| 问题 | 我的答案要点 |
| --- | --- |
| 你怎么控制 AI 成本？ | 四层：① 按 `textHash + promptVersion + modelVersion` 缓存，重复审查零调用；② 单份合同调用次数硬上限（超过就失败，不继续调）；③ 令牌桶限流 + 日预算上限；④ **开发和测试默认走 Mock 通道（`AI_ENABLED=false`），只有演示和验收才开真实调用**。 |
| 为什么要设"单合同调用次数上限"？ | 因为真实风险不是"额度不够"，而是**调试时的循环调用把额度烧光**——比如缓存没生效，跑一次集成测试就 20 次调用，跑十遍就 200 次。上限让问题在第一个异常调用时就暴露，而不是等到额度见底。**成本也是一种正确性约束。** |
| 超预算时系统怎么做？ | 明确返回 `AI_BUDGET_EXCEEDED` 并提示用户，**绝不静默降级成"审查通过、未发现风险"**。把"没审"伪装成"没问题"是最严重的误导。 |

### 3.8 通用追问

| 问题 | 我的答案要点 |
| --- | --- |
| 这个项目最难的地方？ | 不是调模型，是**让模型的输出变得可验证**。证据对齐那一段我改了三次：最初只做严格字符串匹配，发现归一化后区间偏移；后来补了坐标回映射和对应的边界测试。 |
