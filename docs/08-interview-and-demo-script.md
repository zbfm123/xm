# 合同智能审查平台 · 秋招面试与验收脚本

> [!important] 这份笔记为什么单独存在
> 通用模板的"交付物"是给客户的软件。**本项目的交付物是"我在面试里能讲出来的东西"。**
> 软件只是证据。所以每个技术决策都必须能反向回答："面试官会怎么追问，我答什么。"

## 1. 简历怎么写

### 项目条目（4~6 行，STAR 收敛）

~~~text
合同智能审查平台 | Java 后端 · 个人项目 | 2026.10（5 天冲刺）

· 面向法务审合同场景，实现"上传 → 解析 → 要素抽取 → 规则校验 → AI 风险识别 → 人工复核"
  完整闭环。后端 Spring Boot 3.3 / Java 21 / MyBatis-Plus / MySQL / Redis；
  自带单文件调试台（零构建，浏览器可走完整流程）。
· 设计"规则引擎 + AI 增强"双通道架构：金额一致性、日期逻辑、必备条款缺失、主体一致性等确定性校验
  由纯函数规则引擎实现，不联网、结论可复现；AI 仅产出候选风险条目；两者互不调用，只在工作流层汇合。
· 规则结果为三态（命中 / 通过 / **无法判定**）而非布尔：要素抽不到时返回"无法判定"并写明缺哪个字段，
  避免系统在信息不足时输出"合同合规"。
· 解决大模型引用幻觉：实现三级证据对齐（精确 / 归一化+坐标回映射 / 模糊），
  AI 结论必须能在原文定位到字符区间，否则标 EVIDENCE_MISMATCH 并转人工，**不进报告正文**。
· 人工复核留痕采用只追加审计：接口层无修改入口、数据库层触发器拒绝改动、再加哈希链可检测篡改；
  5 天期限内主动砍范围保质量：推迟统计看板、批量审查、报告导出与 OCR。
~~~

> [!tip] 加分的写法
> 把"5 天"写进去不是减分项，而是**主动展示范围管理能力**。
> 面试官会立刻追问"5 天你怎么取舍的"——这正是你准备好的答案（见下方"期限与取舍"小节）。

### 一句话版本（自我介绍/电梯陈述用）

> 我做了一个合同智能审查平台，重点不在"接了 AI"，而在**给概率性的 AI 输出加上工程约束**：AI 只能产出带原文证据和置信度的候选结论，能不能采信由确定性规则和人工决定。

### 写简历时的红线

- ❌ 不写"精通"、不写"高并发"（除非真有压测数据，见 [07](07-change-and-delivery.md#已知限制)）。
- ❌ 不写没做过的模块名充数。
- ✅ 每一个技术名词，都要能答出"为什么用它、不用它会怎样"。

## 2. 演示脚本

### 演示前准备（30 秒）

```powershell
.\run-dev.ps1          # 默认 Mock 桩，零 AI 消耗，不需要网络
```

打开 <http://localhost:8080/app/>，用 `staff01` / `Demo@2026` 登录。

**启动时会自动准备 3 份虚构合同**，已跑完解析、规则、AI 审查。列表里直接能看到：

| 合同 | 规则结果 | AI 结果 | 用来讲什么 |
| --- | --- | --- | --- |
| **演示-要素齐全** | 4 条全 `PASS` | 0 条候选 | 正常链路 |
| **演示-要素缺失** | 3 条 `UNDETERMINED` + 1 条 `PASS` | **1 条证据不匹配** | **三态设计 + 证据对齐** |
| **演示-含风险条款** | 1 命中 / 1 通过 / 2 无法判定 | 4 条候选，全部可定位 | AI 审查 + 人工复核 |

> [!tip] 兜底准备
> 1. **录一段 3 分钟视频**——现场网络、额度任何一个出问题都不至于开天窗。
> 2. 全程**不需要网络**：Mock 桩是应用内的，开关是 `AI_ENABLED`。
> 3. 想演示"AI 挂了"那一幕：把启动命令换成
>    `$env:AI_CLIENT_MODE="unavailable"; .\run-dev.ps1`，
>    降级是**确定性**的，不依赖拔网线。

### 3 分钟版（严格按这个顺序讲，三个"绝不砍"各一段）

| 时间 | 点什么 | 我要说的话（要点） |
| --- | --- | --- |
| 0:00-0:20 | 打开列表 | "合同审查工作台。链路是 上传→解析→抽取→规则→AI→人工复核。启动后这三份是演示数据，已跑完。" |
| 0:20-0:50 | 点开**要素缺失**那份的规则结论 | "这是本项目第一个核心设计：**规则结果不是布尔，是三态**。命中/通过/**无法判定**。这里三条是'无法判定'，因为合同没写金额和日期。如果我把'抽不到'当成'通过'，系统就会在**什么都不知道的时候告诉用户合同没问题**——这比报错危险得多。" |
| 0:50-1:30 | 点开**要素缺失**那份的 AI 结论 | "第二条：**证据对齐**。大模型会给引文，但会幻觉。所以每条引文都要**回到原文机器校验定位**。你看这条状态是 `EVIDENCE_MISMATCH`、位置为空、**不进报告正文**。定位不上就转人工，**绝不猜一个'差不多'的位置**——给错位置比不给更糟，人工会跳到无关的地方然后以为定位错了。" |
| 1:30-2:10 | 点开**含风险条款**那份，对一条结论点"采纳" | "第三条：**只追加审计**。AI 给候选，**人做决定**。这里所有条目的初始状态都是候选态，**没有'已生效'这个状态**。我采纳一条，会写一条不可修改的记录：谁、何时、对哪条、什么理由、状态从什么变成什么。" |
| 2:10-2:35 | 点"校验审计链" | "这条记录用哈希链串起来，每条包含前一条的哈希。直接改数据库会被 MySQL 触发器拒绝；即使有人关掉触发器改了，链会断并指出是哪一条。" |
| 2:35-3:00 | 重启应用，换成 `AI_CLIENT_MODE=unavailable` | "最后：**AI 挂了系统还能用吗？** 能。任务停在'AI 不可用（已降级）'——不是'完成'，也不是终态。规则那四条结论还在，我可以继续人工复核。**如果把 AI 失败当成任务失败，规则引擎做得再准也没意义，因为用户根本走不到看结论那一步。**" |

### 15 分钟版（技术面深聊，按追问方向挑 3~4 条）

1. **TDD 不是嘴上说的**：打开 `ReviewTaskStatusMachineTest`，指那段 **6×6 穷举**
   （"状态机的缺陷几乎总是某条边漏了或被意外打开，只测典型路径发现不了"），
   再指 `AppendOnlyAuditContractTest` 的反射扫描
   （"加了 update/delete 方法，构建就失败。**注释不会阻止任何人，构建失败会**"）。

2. **异常分支怎么测**：`DeepSeekClientTest` 用 **MockWebServer 起真实 HTTP 服务端**
   ——"mock 我自己的接口只能验证'调用发生过'，**测不到 HTTP 状态码映射、超时、响应体解析**这些真正容易出错的地方"。

3. **成本控制**：讲 `AiCostGuard` 的双上限，以及"真正的风险不是额度不够，而是**调试时的循环调用**"。

4. **Git 提交历史**：`test(...)` → `feat(...)` → `fix(...)` 的原子序列。
   特别指 `fix(ai): run model calls in their own transaction so degradation can commit`
   ——那是一个**单测全绿但真实调用挂掉**的 bug。

5. **现场跑一次全量测试**：`mvn test` → **272/272**。

> [!warning] 不要说的两件事
> 1. **不要说"不可篡改"**。哈希链防**篡改**，不防**抵赖**——
>    知道算法的人可以重算整条链。真正的不可抵赖需要外部时间戳或签名服务。
>    **主动说出这个边界，比等人追问要好。**
> 2. **不要说规则集"覆盖了法务风险"**。严重级别目前凭业务常识设定，
>    **没有真实法务依据**。真实系统的级别应当来自业务方的风险清单。

## 3. 面试问答（按模块）

> [!tip] 用法
> 每答完一个模块的问题，就在对应模块笔记的「面试可讲点」里补一条。
> 答不出来的先写进下面的「待补」区，别编。

### 3.1 架构与选型

| 问题 | 我的答案要点 |
| --- | --- |
| 为什么不用微服务？ | **两个原因，第二个更重要。** 一是 5 天期限、单人开发、无真实流量，微服务只增加运维成本；二是**我没有微服务实践经验**，硬搭一个只会得到"照教程搭出来的东西"，反而经不起追问。我的替代方案是模块化单体 + 明确的边界纪律：模块间只走接口、禁止跨模块读表、依赖方向单向、`rule` 与 `ai-review` 互不调用。**架构能力体现在边界划得清，不体现在拆得多。** |
| 为什么不用 Flyway？ | 坦白说是我没学过，而 5 天期限内不值得为它花一天。我用 `schema.sql` + `data.sql` + `CREATE TABLE IF NOT EXISTS` 满足了"启动即建表、可重复执行"。**我清楚这笔技术债的代价**：没有版本化迁移，改表只能手工 ALTER，多人协作环境会出问题。如果给我一周，Flyway 是第一件要补的事。 |
| 5 天你怎么取舍的？ | 我先定死一条线：**证据对齐、降级路径、审计只追加**三项绝不砍，因为它们是这个项目的唯一技术卖点。其余全部按"演示时能不能看出来"排序砍，砍掉了统计看板、批量审查、报告导出、OCR。**砍范围，不降质量。** 最后 20 个任务按天排，每天必须有一个可演示的产物，避免最后一天才发现跑不起来。 |
| 模块之间怎么保证不互相污染？ | 两条硬纪律：`rule` 与 `ai-review` **互不调用**（确定性判断不付概率代价），两者只在 `workflow` 汇合；跨模块禁止直接读表。违反了先改架构文档再改代码。 |
| 你系统里最重要的不变式是什么？ | I-02：**无原文定位的 AI 结论不得进入正式结论**。这条把"AI 会不会胡说"变成了一个可机器校验的问题，而不是靠信任。 |
| 为什么把证据对齐做成独立一层？ | 因为模型会幻觉出不存在的条款，而且幻觉的形式是"看起来很像的改写"。如果信任模型的引用，报告里会出现无法核实的判断，法务的信任成本极高。所以对齐必须是机器校验、必须有单测、失败必须显式降级。 |

### 3.2 规则引擎

| 问题 | 我的答案要点 |
| --- | --- |
| 规则为什么不用 AI 做？ | 金额大小写不一致、签署日晚于生效日、缺必备条款，这些都是**确定性判断**。用 AI 做会引入不确定性、成本和不可复现性，还无法写严格单测。AI 留给"语义模糊"的部分（比如"这条违约责任是否明显不对等"）。 |
| 怎么保证同输入同输出？ | 规则执行是纯函数：输入 = 归一化文本 + 要素，输出 = `RuleFinding[]`，内部不读时间、不读随机数、不联网。有"连续执行两次结果完全一致"的回归测试。 |
| 规则怎么扩展？ | 每条规则实现统一接口（`ruleCode` / `severity` / `evaluate(context)`），引擎按注册表遍历。新增规则不改引擎。**但我没做可视化规则编排**——这是已知限制，因为本期没有真实用户来驱动这个需求。 |
| 边界情况怎么处理？ | 要素缺失时不猜：规则返回"无法判定"而不是"通过"。**"通过"和"无法判定"必须是两种不同结果**，否则缺失必备条款会被当成合规。 |

### 3.3 AI 接入（重点追问区）

| 问题 | 我的答案要点 |
| --- | --- |
| 怎么防止大模型胡说？ | **四道闸门**：① 提示词约束 schema（含 riskType 枚举）；② 返回后 schema 校验，非法就 `SCHEMA_INVALID` **整体丢弃**，不部分采纳、不填默认值、不静默截断；③ **证据对齐**——引文必须能在原文定位到字符区间，否则 `EVIDENCE_MISMATCH` 转人工、**不进报告正文**；④ 置信度裁决，低于阈值强制人工复核。最后所有 AI 结论的初始状态都是候选态，**没有"已生效"这个状态**。 |
| 大模型返回的引用被改写了怎么办？ | 对齐算法不只做严格匹配，还做归一化匹配（全角/半角、空白折叠），但**归一化后的区间必须回映射到原文坐标**——这正是我踩过的坑，也是我专门写了测试的地方。 |
| AI 成本怎么控制？ | 四层：① 按 `textHash + promptVersion + model` 缓存，同文本第二次 **0 次外部调用**；② **单份合同调用次数硬上限**，超过直接失败；③ **日预算上限**，把 token 换算成估算金额累计；④ 超限时**明确拒绝并提示**，绝不静默降级成"审查通过"。**我没有做分布式限流**——计数在内存里，多实例部署时必须换 Redis，这是已知限制。 |
| AI 挂了系统还能用吗？ | 能。规则审查和人工复核完全不依赖 AI。AI 不可用时对应任务标 `AI_UNAVAILABLE`，界面明确提示，规则结论照常展示（I-04）。这是设计出来的，不是碰巧。 |
| 重试策略？ | 超时/限流最多重试 1 次，之后转人工。**不做无限重试**——这是从工作流方法里抄来的纪律：重试掩盖的根因，最终会以更贵的方式出现。 |
| 为什么不用 Spring AI 这类框架，自己写 HTTP？ | 我只有 DeepSeek 一个供应商，自写客户端约 100 行，没有版本不确定性，供应商耦合集中在一个 `DeepSeekClient` 类里。更关键的是**可测试性**：我把调用封在 `AiClient` 接口后面，测试注入桩实现就能覆盖超时/限流/非法 JSON 三类分支；同一个开关（`app.ai.enabled=false`）还直接复用为演示时的降级手段，**一个设计同时解决测试和降级两个问题**。 |
| 落库的 AI 数据你存了什么？ | 风险类型、原文引文、**对齐后的字符区间**、综合置信度、**匹配级别**（EXACT/NORMALIZED/FUZZY）、状态与状态原因、模型版本、提示词版本。提示词版本进缓存键——**改了提示词而缓存键不变会命中旧结论，而且看起来完全正常**。人工复核的每条记录另存操作人、理由、动作前后的状态，并用哈希链串起来。 |
| 有没有做评测集？ | 没有，这是已知短板。我只有少量虚构合同做回归。我更愿意说清楚：没有评测集的情况下，我把 AI 定位成"候选建议"而不是"自动结论"，这是在缺评测能力时更诚实的架构选择。 |

### 3.4 并发、幂等与数据一致性

| 问题 | 我的答案要点 |
| --- | --- |
| 批量审查怎么做的？ | **本期没做，我主动砍掉的。** 理由是 5 天里它的性价比最低，而且演示时看不出差别。设计上是串行执行、不并发——外部平台有速率限制，并发放大的是失败而不是吞吐，而且并发会让"哪个命令属于哪个任务"难以追踪。**我宁可说清楚没做，也不想在简历上写一个没实现的功能。** |
| 幂等怎么保证？ | 三处各有幂等键：上传用**文件内容哈希**、审查任务与复核动作用**调用方提供的幂等键**。实现靠**数据库唯一索引**兜底，加上先查后写的短路。**我没有用分布式锁**——唯一索引在并发下同样能保证只有一条，而且不需要额外引入 Redisson。**我在测试里真的踩到过幂等失效**：查重关键字里带了方括号，MyBatis 的 `#{}` 走 OGNL 把方括号当成了列表下标，于是每次启动都重复播种。 |
| 事务边界怎么划的？ | **AI 调用走独立事务（`REQUIRES_NEW`）**——不是因为它慢，而是因为内层 `@Transactional` 抛异常会把外层标记成 rollback-only，**调用方 catch 住也没用，提交时照样整体回滚**。这个 bug 单测全绿、真实 HTTP 调用才暴露（见 T-019）。文件写入我**确实放在了上传事务内**，因为文件存储是**内容寻址**的（路径由哈希决定），同一份内容重复写是幂等的，失败重试安全。 |
| 租户隔离怎么防止漏掉？ | 每条 SQL 都带 `tenant_id`，并且有一条**架构测试在构建时扫描所有 `@Mapper` 接口的 SQL**——谁写了一条不带 `tenant_id` 的查询，构建直接失败。我还验证过这条测试真的会失败（手工去掉一个 `tenant_id` 看它报错），否则它就是个摆设。**用测试锁住不变式，而不是靠代码评审。** |

### 3.5 认证与安全

| 问题 | 我的答案要点 |
| --- | --- |
| 登出为什么要幂等？ | 用户重试、前端重复调用，诉求都是"让这个令牌失效"——**而它已经失效了**。失败响应只会让前端多写一个无意义分支。所以我把登出设为免认证：令牌本身就是凭证，有效就拉黑，无效就什么都不做。**这个结论是测试逼我改的**：我原本要求登出必须已认证，结果"重复登出返回 401"，我选择改代码而不是改测试。 |
| 密码错误和账号不存在为什么返回同一个错误码？ | 否则登录接口会变成**账号探测器**——攻击者能靠错误码区分出哪些用户名存在。防爆破交给锁定计数，不靠差异化提示。 |
| 锁定状态为什么落库而不是只放 Redis？ | 清一次缓存就等于给攻击者重置了爆破机会。**安全状态不能依赖可被清空的存储。** |
| 登出黑名单为什么设 TTL？ | TTL = 令牌剩余有效期。令牌自然过期后再拉黑只是白占内存。这样黑名单大小有上界 = 一个有效期窗口内的登出量，不会无限膨胀。 |
| JWT 里为什么不能放邮箱、真实姓名？ | **JWT 是签名不是加密**，base64 解开就是明文。所以我只用 `UserView` 投影控制对外字段，并有断言确保响应里不出现 `passwordHash`。 |
| 失败计数为什么先检查锁定再验密码？ | 否则锁定期内仍在跑 BCrypt，**锁定形同虚设**，还白白消耗 CPU。校验顺序本身就是设计。 |

### 3.6 文本处理与解析

| 问题 | 我的答案要点 |
| --- | --- |
| **归一化为什么要保坐标？** | 归一化会改变字符长度（全角转半角、空白折叠、去页眉）。只保存"洗干净的文本"，下游所有证据区间就会**整体偏移**，而**症状是文本看起来完全正常、只是引文定位不上**——极难排查。所以我每一步都同步维护「归一化下标 → 原文下标」映射并落库，还写了"映射单调"和"归一化片段能回查原文"两个测试。 |
| 全角转半角有什么坑？ | 最顺手的写法是 `U+FF01..U+FF5E` 整段平移，但中文标点 `，。；：（）` 的全角码位**就在这个区间里**，整段平移会把 `金额：` 变成 `金额:`。我踩过这个坑：注释里写着"刻意不转中文标点"，代码却全转了。**注释和代码不一致时，只有测试可靠。** |
| 扫描件怎么处理？ | 显式报 `NO_EXTRACTABLE_TEXT` 并提示"本期不支持"。**绝不能返回空文本**——那会让下游以为"这份合同没有风险条款"，比报错危险得多。这跟规则引擎的 `UNDETERMINED` 是同一条原则：**"不知道"必须是一种显式结果。** |
| 页眉页脚怎么识别？ | 统计完全相同的短行。我设了三道保守护栏：单页不清理、长于 30 字不清理、正好等于上限也不清理。**宁可留下页眉，也不要误删正文**——留下的页眉人一眼能忽略，删掉的正文没人能找回来。代价是递增页码抓不到，这是已知限制。 |
| 解析失败为什么不抛异常？ | 用户上传加密 PDF 是**预期内的业务结果**，系统正常工作并如实告知。抛异常会让日志里混入大量"预期内的失败"，把真正的异常淹掉。所以我捕获它转成状态返回。 |
| 为什么失败时不能留半份正文？ | "有正文但状态是失败"会让下游不确定该不该用这份文本。唯一不含歧义的方式是：要么完整的正文 + `PARSED`，要么什么都没有 + `PARSE_FAILED`。 |
| DOCX 提取有什么容易漏的？ | **表格内容**。合同里的金额、期限常在表格中，只读段落会**静默丢掉金额**——提取"成功"了，但关键数据不见了。我为这一点单独写了测试。 |
| 提取和归一化为什么要分成两个类？ | 它们是两个关注点：「文件 → 字符串」和「字符串 + 坐标映射」。分开之后归一化的四个步骤各自独立可测，也才能针对"映射是否错位"写专门的断言。 |

### 3.7 CRUD 相关问题（别怕被问到，这是加分点）

| 问题 | 我的答案要点 |
| --- | --- |
| 你这个项目的 CRUD 有什么特别的？ | 单看每一条都不特别，但**每条 CRUD 都挂着一个真实问题**。比如查询要保证多租户隔离不能靠人记得写条件；删除要级联清理文件和缓存。**我不觉得有 CRUD 是缺点，我觉得"CRUD 里没有问题"才是缺点。** |
| **租户隔离你怎么保证不遗漏？** | **不靠自觉，靠构建时检查。** 我写了一个架构测试扫描所有 Mapper 的 SQL，缺 `tenant_id` 就 `mvn test` 失败并指出是哪个类。而且我**验证过这个测试真的会失败**——故意删掉一个条件，它精确报出了 `ContractTextMapper`。另外单独写了一个"确实扫到了 Mapper"的断言，防止"扫到 0 个所以假绿"。 |
| 为什么另一个租户看到的是 404 而不是 403？ | 403 等于确认"这份合同存在，只是不归你"，接口就变成了合同 id 探测器。**不确认自己不该确认的信息。** |
| 删除合同你怎么做的？ | 两段式：先软删除让用户立刻看到结果，再清理磁盘文件、正文行和 **Redis 里该 `textHash` 的 AI 缓存**。清理失败进重试队列，并记录未清理完的 `textHash`。 |
| 为什么删除要清缓存？不清会怎样？ | AI 结果按 `textHash` 缓存。只删库不清缓存，**用户重传同一份合同会拿到与本次无关的过期结论**——而且看起来完全正常，这是最危险的一类 bug。**缓存键按内容算，失效就必须按内容定向清除。** |
| 为什么用文件哈希做幂等而不是文件名？ | 同一份文件改名后重传应当命中已有记录。**幂等看内容，不看名字。** |
| 超限校验为什么写在算哈希之前？ | 否则一个 1GB 的非法文件会被完整读一遍算哈希，白费 IO。**校验顺序也是设计。** |
| 分页怎么做的？ | 常规 `LIMIT/OFFSET`，`size` 收敛在 1~100 防止 `?size=100000` 拖垮数据库。我清楚深分页会退化（`OFFSET` 很大时要扫过前面所有行），演示数据量下没问题；数据量上去要换成游标分页。**这是已知限制，不是我不知道。** |
| 非法参数怎么处理的？ | 显式报错，不静默忽略。这里踩过一个坑：未知状态值抛的 `IllegalArgumentException` 一开始落到了兜底处理器返回 **500**，真实环境复验才发现，改成 400。**服务层测试覆盖逻辑，HTTP 层测试覆盖映射，两者不能互相替代。** |

### 3.8 AI 成本与额度管理

| 问题 | 我的答案要点 |
| --- | --- |
| 你怎么控制 AI 成本？ | 四层：① 按 `textHash + promptVersion + model` 缓存，重复审查**零调用**；② **单份合同调用次数硬上限**（超过就失败，不继续调）；③ **日预算上限**（把 token 换算成估算金额累计）；④ **开发和测试默认走 Mock 通道**，只有演示和验收才开真实调用。**没做分布式限流**——计数在内存里，多实例部署要换 Redis，这是已知限制。 |
| 为什么要设"单合同调用次数上限"？ | 因为真实风险不是"额度不够"，而是**调试时的循环调用把额度烧光**——比如缓存没生效，跑一次集成测试就 20 次调用，跑十遍就 200 次。上限让问题在第一个异常调用时就暴露，而不是等到额度见底。**成本也是一种正确性约束。** |
| 超预算时系统怎么做？ | 明确返回 `BUDGET_EXCEEDED`（HTTP **429**）并标记 `degradable`，**绝不静默降级成"审查通过、未发现风险"**。把"没审"伪装成"没问题"是最严重的误导。任务会停在 `AI_UNAVAILABLE`，规则结论照常可用。 |
