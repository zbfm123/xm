# T-020 前端页面

## 任务边界

- 所属模块：—（跨模块）
- 对应验收：**A-10**（干净机器可演示）
- 目标行为：登录 → 合同列表 → 合同详情 → 审查报告，**全流程可点击完成**
- 前置依赖：T-001 ~ T-019 ✅

## 技术选择：为什么不上 Vue

期限只有 5 天，而演示的价值在"能点完一条闭环"，不在框架。

**原生多页 + 一套共享 CSS/JS** 已经覆盖四个页面，而且：

| 好处 | 说明 |
| --- | --- |
| 不需要 Node | 干净机器上少一个依赖就少一个演示翻车的可能 |
| 不需要构建 | 改完刷新即可，没有"忘了重新 build"这类问题 |
| 后端直接托管 | Spring Boot 静态资源，零额外进程 |

**代价写在技术债里**：没有组件化、没有类型检查、样式靠约定。

> 这不是"不会 Vue"，而是**在 5 天期限下对"什么最不容易翻车"的判断**。
> 如果时间更长，Vue + 类型检查是更好的选择。

## 四个页面

| 路径 | 内容 |
| --- | --- |
| `/app/` | 登录（含演示账号一键填入） |
| `/app/contracts.html` | 合同列表：上传、关键字/状态筛选、分页、删除 |
| `/app/detail.html?id=N` | 详情：要素 / 规则结论 / AI 结论 / 复核历史 / 原文（原文与归一化文本并列） |
| `/app/report.html?id=N` | **审查报告**：浏览器打印，不做导出功能（决策 C-09） |

共享资源：`/app/assets/app.css`、`/app/assets/api.js`

## 两个刻意的视觉决定

### 1. 「无法判定」渲染成**灰色**，不是绿色

如果"无法判定"看起来像"通过"，**三态设计就在用户唯一会看的地方退化成两态**。

CSS 里四类语义色不可互换：

```css
--ok      /* 确定通过 */   绿
--err     /* 命中/失败 */  红
--warn    /* 需人工 */     黄
--unknown /* 不知道 */     灰  ← 必须与 ok 区分
```

### 2. 报告页**自己写明已知限制**

不是埋在文档里，而是写在报告正文第五节：

- 规则严重级别**没有真实法务依据**
- 哈希链**防篡改，不防抵赖**
- 扫描件无法提取文本，会被显式标记而不是当成"无风险"
- "未列出风险" ≠ "不存在风险"
- 不构成法律意见

> 报告是给人看的产物，**它的边界就该写在它自己身上**。

## 实施日志：写页面暴露了 3 个后端缺口

**这是本任务最有价值的部分**——测试没抓到，因为**从来没人渲染过这些数据**。

### 缺陷 1：`/ai-findings` 不返回 `id`

前端的「采纳/驳回」按钮拿不到 `findingId`。

**失败方式最恶劣：点了没反应，且不报错。** 没有异常、没有日志，就是什么都不会发生。

修复：响应里加 `id`。

### 缺陷 2：`/text` 只返回归一化文本

证据区间是**原文坐标**。人工拿归一化文本去核对会**整体错位**，于是会得出"系统定位错了"的结论，而实际是核对时用错了文本。

修复：同时返回 `originalText`。详情页把两份并列展示，让人看清它们确实不同。

### 缺陷 3：`/app/` 返回 500，而 `/app/index.html` 正常

目录形式的路径落到 Spring Boot 静态资源处理器，**行为不确定**。

修复：加 `FrontendEntryController` 显式 302 重定向到 `/app/index.html`。

> **不依赖框架的目录索引行为**——那种行为在不同版本下会变，
> 而它出问题的位置恰好是**演示的第一屏**。

## 顺带修的两个"自己挖的坑"

### 临时验证脚本差点进仓

`_v5.py` 躺在仓库外，`git ls-files` 确认从未被跟踪——虚惊。

但既然反复犯，加了 `.gitignore` 兜底规则（`_*.py` / `_*.java` / `_*.txt` / `_*.sql`）。

### `push.ps1` 的 BOM 被编辑工具剥掉

正是我踩过两次的坑。**而脚本的 BOM 检查只查了一个方向**：
它拒绝 java/yml 带 BOM，却把".ps1 必须有 BOM"只写在注释里。

现在**双向都查**，失败时直接打印修复命令，且排在其它检查之前（消息不被淹没）。

### 敏感信息扫描误报

它把登录页里的 `password: document.getElementById('password').value`
当成硬编码凭据——**那是取值代码，不是字面量**。

修复：正则匹配到的值若紧跟 `(` 或 `.`，判为表达式而非字面量。

> **扫描器一旦开始误报，人就会习惯性加 `-SkipSecretCheck`，
> 等真的泄露时也一样跳过。它的价值取决于它有多可信。**

## 完成结论

- 状态：**已验收**

### 面试可讲点

1. **前端为什么不上 Vue？** → 5 天期限下，演示的价值在"能点完一条闭环"，不在框架。原生多页 + 共享 CSS/JS 已经覆盖四个页面，而且**不需要 Node、不需要构建**——干净机器上少一个依赖就少一个演示翻车的可能。**这不是"不会 Vue"，是在期限下对"什么最不容易翻车"的判断。** 代价写在技术债里：没有组件化、没有类型检查。
2. **"无法判定"为什么用灰色？** → 如果它渲染成绿色，**三态设计就在用户唯一会看的地方退化成两态**。颜色语义在这个项目里不是审美问题：绿=确定通过、红=命中、黄=需人工、**灰=不知道**，四类不可互换。
3. **报告为什么要自己写限制？** → 报告是给人看的产物，**它的边界就该写在它自己身上**，而不是埋在没人读的文档里。里面写明：规则级别没法务依据、哈希链不防抵赖、"未列出风险"不等于"不存在风险"。
4. **写前端发现了什么后端问题？** → 三个，而且**测试全都抓不到，因为从来没人渲染过这些数据**：`/ai-findings` 不返回 `id`（按钮点了没反应且不报错）、`/text` 只返回归一化文本（区间是原文坐标，核对会错位）、`/app/` 目录形式返回 500。**"没人用过的接口"和"能用的接口"是两回事。**
5. **为什么加 `FrontendEntryController` 做重定向？** → 目录形式路径落到静态资源处理器，**行为依赖框架版本**。而它出问题的位置恰好是演示的第一屏。**不依赖框架的隐含行为，尤其是第一屏。**
