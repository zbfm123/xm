# T-009 / T-010 文本提取 · 保坐标归一化 · 解析失败显式化

## 任务边界

- 所属模块：[parse](../modules/parse.md)
- 对应需求/验收：F-02、**A-02**（解析失败显式化）、A-03 的基础
- 目标行为：
  - 上传 PDF/DOCX 后能解析出**归一化文本**，并落库
  - 归一化后仍能把任意位置**回查回原文**（这是不变式 I-02 的前提）
  - 解析失败时状态置 `PARSE_FAILED` 并给出**可区分的错误码**，且**不留下半份正文**
- 本任务不做：条款切分与证据对齐算法（T-013）、AI 调用（T-014）
- 前置依赖：T-006（上传与存储）✅
- 涉及的不变式：**I-02 的实现前提**、I-05（重复解析幂等）

> [!important] 为什么归一化必须"保坐标"
> 归一化会改变字符长度（全角转半角、空白折叠、去页眉页脚）。
> 如果只保存洗干净的文本，下游的 AI 引文会**整体偏移**，
> 而症状是"文本看起来完全正常，只是证据定位不上"——极难排查。
> 因此每一步归一化都必须同步维护「归一化下标 → 原文下标」映射。

## 验收示例

### 正常路径

- 给定：已上传一份文本型 PDF
- 当：`POST /api/contracts/{id}/parse`
- 则：状态 `UPLOADED → PARSING → PARSED`，正文与 `textHash` 落库，偏移映射可回查原文

### 异常路径

| 情况 | 期望 |
| --- | --- |
| 加密 PDF | 200 + `success=false`、`PDF_ENCRYPTED`，状态 `PARSE_FAILED`，**无正文行** |
| 纯图片/空白 PDF（扫描件） | `NO_EXTRACTABLE_TEXT`，提示"疑似扫描件（本期不支持）" |
| 损坏 PDF | `PARSE_FAILED` |
| 重复解析 | 幂等，返回"已解析，未重复处理"，不重复写正文 |
| 跨租户解析 | 404 `CONTRACT_NOT_FOUND` |
| 已删除合同 | 404 |
| 未解析就取正文 | 明确失败（"合同尚未解析成功"），**不返回空文本** |

### 明确不该发生的事

- 归一化后映射数组长度与文本长度不一致（有构建期自检 `assertConsistent()`）
- 解析失败却写入了正文行
- 扫描件被当成"没有风险条款"的空合同继续流转
- **误删正文**：页眉页脚清理宁可漏删，也不能删掉真实条款

### 归一化步骤顺序（不能随意调换）

1. **统一换行**——后续按行处理的前提
2. **全角转半角**——先转换，空白折叠才能识别全角空格 `U+3000`
3. **去页眉页脚**——此时行结构规整，统计重复行才准确
4. **折叠空白**——最后统一收尾

## 实施日志（短期）

本任务暴露并修复了 **3 个真实缺陷**，都值得记录：

1. **全角转半角把中文标点也转了。**
   实现时用了 `U+FF01..U+FF5E` 整段平移，而中文标点 `，。、；：（）` 的全角码位
   同样落在该区间，于是 `金额：` 变成了 `金额:`。
   **注释里写着"刻意不转中文标点"，代码却没做到——注释和代码不一致时，只有测试可靠。**
   改为只转换全角数字与字母。

2. **折叠空白时挂起的换行没落盘就丢弃了。**
   导致被删行两侧的正文粘连成一段（`第一页正文内容：…第 1 页第二页正文内容`）。
   根因是 `pendingNewline` 的分支逻辑错误。

3. **删行时把行与行之间的换行符一起删掉了。**
   原实现"边遍历边删除"，只复制保留行的内容而丢掉了分隔换行。
   改为**先决定保留哪些行，再用 `\n` 重建文本**。

此外还修正了两处**测试断言错误**（代码是对的）：

- 我断言递增页码 `第 1 页` / `第 2 页` 会被当作页脚删除。
  但每页文本不同，重复行判定抓不到它们——**这是刻意保留的保守行为**，不是缺陷。
  误删正文的代价远高于留下页码。
- 我用的"长句"示例正好 40 字，卡在当时的阈值 `<= 40` 边界上被删掉。
  这说明阈值太激进：40 字完全可以是一句真实的重复条款。
  **收紧为 `< 30`**（严格小于）。

## 完成结论

- 状态：**已验收**

### 一次阈值收紧体现的取舍

页眉页脚清理是**启发式规则**，不可能全对。我明确选择了倾向：

> **宁可留下页眉，也不要误删正文。**
> 留下的页眉人一眼能忽略；删掉的正文没人能找回来。

因此：单页文档不清理、长于 30 字的行不清理、正好等于上限的行也不清理。
代价是递增页码与长页眉会残留——这是**已知限制**，需要页首/页尾位置信息才能进一步改进。

### 新增/变更的错误码

复用 `PDF_ENCRYPTED`、`NO_EXTRACTABLE_TEXT`、`PARSE_FAILED`、`CONTRACT_NOT_FOUND`。
新增接口：`POST /api/contracts/{id}/parse`、`GET /api/contracts/{id}/text`。

### 面试可讲点

1. **归一化为什么要保坐标？** → 归一化会改变字符长度。只保存"洗干净的文本"会让下游所有证据区间整体偏移，而**症状是文本看起来完全正常、只是引文定位不上**，极难排查。所以我每一步都同步维护「新下标 → 原下标」映射，并有"映射单调"和"归一化片段能回查原文"的测试。
2. **全角转半角有什么坑？** → 最容易的写法是 `U+FF01..U+FF5E` 整段平移，但中文标点 `，。；：` 的全角码位就在这个区间里，整段平移会把中文标点变成半角。**我踩过：注释里写着"不转中文标点"，代码却全转了。** 改成只转全角数字与字母。
3. **扫描件怎么处理？** → 显式报 `NO_EXTRACTABLE_TEXT` 并提示"本期不支持"。**绝不能返回空文本**——那会让下游以为"这份合同没有风险条款"，比报错危险得多。
4. **页眉页脚怎么识别？** → 统计完全相同的短行。我设了三道保守护栏：单页不清理、长于 30 字不清理、正好等于上限也不清理。**宁可留下页眉，也不要误删正文**——留下的页眉人一眼能忽略，删掉的正文没人能找回来。代价是递增页码抓不到，这是已知限制。
5. **解析失败为什么不抛异常？** → 用户上传加密 PDF 是**预期内的业务结果**，系统正常工作并如实告知。抛异常会让日志混入大量"预期内的失败"，真正的异常被淹没。所以我捕获 `ContractException` 转成状态返回。
6. **为什么失败时绝不能留半份正文？** → "有正文但状态是失败"会让下游不确定该不该用这份文本。唯一不改两可的方式是：要么完整的正文+`PARSED`，要么什么都没有+`PARSE_FAILED`。
7. **DOCX 提取有什么容易漏的？** → **表格内容**。合同里的金额、期限常在表格中，只读段落会**静默丢掉金额**——提取"成功"了，但关键数据不见了。我为这一点单独写了测试。
