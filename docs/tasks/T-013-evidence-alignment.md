# T-013 证据对齐算法

## 任务边界

- 所属模块：[extract](../modules/extract.md)
- 对应需求/验收：**F-05 / F-06 / A-05 / A-06**、不变式 **I-02**
- 目标行为：
  - 把大模型给出的引文**机器校验地定位回原文坐标**
  - 定位不上就**明确失败**，不返回近似区间
  - 匹配强度分级，供下游调整置信度
- 本任务不做：AI 调用本身（T-014）、审查流程（T-016）
- 前置依赖：T-009（归一化与坐标映射）✅
- 涉及的不变式：**I-02**（无原文定位的 AI 结论不得进入正式结论）

> [!important] 为什么这是项目核心
> 大模型会"幻觉"出原文里并不存在的条款，而且幻觉的形式是**看起来很像的改写**。
> 如果直接信任模型给出的引用，报告里就会出现无法核实的判断。
> 这个类把"AI 说的对不对"变成了一个**可机器校验**的问题。

## 三级匹配策略

| 级别 | 策略 | 权重 | 为什么需要 |
| --- | --- | --- | --- |
| `EXACT` | 逐字匹配 | 1.0 | 最可信，但实际少见——模型总有细微改写 |
| `NORMALIZED` | 归一化后匹配，**区间回映射到原文** | 0.9 | 覆盖全角/半角、空白差异的大多数情况 |
| `FUZZY` | 编辑距离相似度 ≥ 0.80 | 0.7 | 容忍个别字差异，**但必须下调置信度** |
| `NONE` | 未命中 | 0.0 | 转人工，**不返回位置** |

分级的本质：**把"匹配有多硬"显式变成一个可裁决的数字**。没有分级，"改了一个字的引文"与"逐字相同"会被同等对待。

## 三条绝不妥协的纪律

1. **匹配到多处且无法消歧 → 判失败**，不擅自选一个位置
2. **找不到 → 返回未命中，不返回近似区间**。
   给一个"差不多"的位置比不给更糟：人工会跳到无关的地方，然后以为系统定位错了地方，而不是以为定位失败了
3. **引文过短（< 6 字）→ 判失败**。"甲方"能命中全文，但它没有证据价值

这三条在类型层面就有保障：`AlignmentResult` 的构造函数**拒绝**"未命中却带位置"和"命中却不带位置"两种状态。

## 实施日志（短期）

本任务踩了 **4 个坑**，前 3 个是真 bug：

### 缺陷 1：相似度算法用了 `Set` 存二元组，丢失频次信息

第一版用二元组集合的 Dice 系数。**用 `Set` 会丢掉频次与位置信息**，
实测中"完全不同的两句话"也得到 **1.0** 的相似度——模糊匹配实际上完全失效。

改为编辑距离后区分度良好（实测：差 1 字 0.96、差 2 字 0.92、
同义改写 0.48、**完全不同的句子 0.07**）。

> 教训：**集合运算会丢频次**。做相似度计算前先想清楚"顺序和重复是否携带信息"。

### 缺陷 2：分级判据错了两次

最初用 `normalizedQuote.equals(quote)` 判断是否"归一化匹配"——
但引文被改写不代表归一化被用到。

第二版拿"原文片段"跟"归一化引文"比——**量纲不一致**，
原文含多余空白时二者天然不同，但仍应算 `NORMALIZED`。

第三版才正确：比较**归一化文本上的那一截**与**原文上的那一截**，
不同说明匹配确实依赖了归一化。

### 缺陷 3：`normalizeQuote` 与文本归一化的口径不一致

`TextNormalizer` 的行为是"保留换行、删除行尾空白、丢弃行首缩进"。
于是 `"付款方式：\n分两期"` 归一化后**冒号后没有空格**，
而引文通常是 `"付款方式： 分两期"`（有空格）——两者对不上，
**本该精确命中的证据被迫退化成模糊匹配，置信度凭空下降**。

修复：把换行也按普通空白折叠为空格。文本侧与引文侧自此一致。

> 这个缺陷是靠"测试里复用生产归一化逻辑"才暴露的。
> 如果测试自己造一份假映射，永远不会发现两条归一化路径不一致。

### 缺陷 4（下游连带）：正则依赖换行做边界

改完归一化后，`RuleCheckServiceTest` 立刻失败：
`PARTY_A` 抽成了 `"上海某某贸易有限公司 签订日期：2026-01-01 生效日期：2026-01-"`。

根因：正则用 `[^\n；;，,]{2,40}` 取值，**而归一化后文本里已经没有换行可依赖**，
于是贪婪地吞掉了后面几十个字。

修复：改用 `\S`（非空白）取值，遇到第一个空格即停止。
公司名中间的空格会截断名称——这是**刻意的取舍**：
截断的名称仍能在正文中命中，而贪婪匹配产出的超长"名称"根本不可能命中、会稳定误报。

### 补充：发现数据模型缺了一列

`contract_text` 原本只存归一化文本与偏移映射，**没有存原文**。
但证据对齐必须能按原文坐标取出片段——只存归一化文本 + 映射，
等于把映射映射回自己。

补了 `original_text` 列。这是必要数据，不是冗余。

> 顺带暴露了不用 Flyway 的代价：`CREATE TABLE IF NOT EXISTS` 不会给已有表加列，
> 我手工执行了一次幂等的 `ALTER TABLE`（用 `information_schema` 判断列是否存在）。
> 这笔技术债已经登记在 [README](../../README.md#5-已知限制与技术债)。

### 测试断言修正 2 处（代码是对的）

- 边界用例用了 4 字的引文（`"开头部分"`），会先被判 `TOO_SHORT`——
  是我测试数据没考虑最小长度阈值。
- 断言"缺条款应有位置"：**缺失的条款在文中不存在**，不可能有位置。

## 完成结论

- 状态：**已验收**

### 面试可讲点

1. **怎么防止大模型编造原文里没有的条款？** → 我实现了一个**证据对齐层**：模型给出的引文必须在原文里机器校验地定位到，否则标记失败并转人工。**核心思路不是让模型更准，而是让它的错误变得可检测。**
2. **匹配为什么分三级？** → 因为"改了一个字的引文"和"逐字相同的引文"可信度显然不同。分级把**匹配强度**显式变成**置信度权重**（1.0 / 0.9 / 0.7），下游据此调整。没有分级，就没有可裁决的依据。
3. **定位不上时怎么办？** → 明确失败，**不返回近似区间**。给一个"差不多"的位置比不给更糟：人工会跳到无关的地方，然后以为系统定位错了，而不是以为定位失败了。这一点在类型层面就锁住了——构造函数拒绝"未命中却带位置"。
4. **同一句话在文中出现多次怎么办？** → 判 `AMBIGUOUS` 并转人工，不擅自选一个。如果调用方还能提供上下文，就用上下文选出最贴近的一处（相似度需 ≥ 0.5 才采用）。
5. **为什么引文太短也要判失败？** → "甲方"能命中全文，但它作为风险条款的证据毫无价值。阈值设 6 字。
6. **相似度用什么算法？** → 编辑距离。**我第一版用二元组集合的 Dice 系数，结果完全不同的两句话也得到 1.0——因为 `Set` 丢掉了频次与位置信息。** 换掉后区分度良好（完全不同 0.07，差 1 字 0.96）。
7. **归一化和证据对齐是什么关系？** → 对齐在**归一化文本**上做（这样全角/半角、空白差异自然被覆盖），但结果必须**回映射到原文坐标**。这两条路径的口径必须完全一致，否则本该精确命中的证据会静默退化成模糊匹配——**这个坑我踩了，是靠"测试复用生产归一化逻辑"才发现的。**
